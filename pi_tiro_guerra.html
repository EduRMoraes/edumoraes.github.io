Biblioteca
do Tiro de Guerra

Sistema computacional para organização e controle do acervo da biblioteca do Tiro de Guerra, desenvolvido como aplicação desktop em C#, Windows Forms e MySQL.

C#Windows FormsMySQLEngenharia de Computação

01 · Visão geral

Um problema real.
Uma solução digital.

O projeto nasceu de uma necessidade identificada no Tiro de Guerra: o controle de empréstimos e devoluções da biblioteca era realizado manualmente, por meio de anotações físicas. Esse modelo dificultava a organização, a rastreabilidade dos livros e a gestão do acervo.

A proposta foi desenvolver um sistema dedicado à biblioteca, centralizando os dados e digitalizando as principais operações.

01 / PROBLEMA

Controle manual

Registros físicos e planilhas isoladas aumentavam o risco de perda de informações e dificultavam o acompanhamento dos empréstimos.

02 / OBJETIVO

Centralização

Organizar o acervo, cadastrar livros e controlar empréstimos e devoluções em uma única aplicação.

03 / SOLUÇÃO

Sistema desktop

Aplicação em C# e Windows Forms integrada a um banco de dados MySQL.

02 · Arquitetura

Como a solução
foi construída.

A aplicação foi desenvolvida como software desktop. O C# concentra as regras de negócio e a integração com os dados, enquanto o Windows Forms fornece a interface gráfica. O MySQL centraliza o armazenamento relacional.

InterfaceWindows Forms

Formulários para login, cadastro, consulta, empréstimos e relatórios.

AplicaçãoC# / POO

Regras de negócio e representação dos dados por objetos.

PersistênciaMySQL

Armazenamento estruturado e relacionamentos do sistema.

FLUXO PRINCIPAL

Usuário → Windows Forms → C# → MySQL
Cadastro → Consulta → Empréstimo / Devolução → Atualização do acervo

05 · Integração com a disciplina

Da teoria
para o sistema.

Os modelos computacionais ajudam a analisar como dados entram, são validados, estruturados e processados. No projeto, alguns conceitos podem ser aplicados diretamente às entradas; outros aparecem como análise arquitetural para futuras integrações.

Nível 3 · Validação léxica

Expressões Regulares + AFD

Entradas como ISBN, campos de login e dados cadastrais podem ser tratadas como linguagens formais. Uma expressão regular define o padrão aceito e um AFD pode representar a decisão de aceitar ou rejeitar a entrada.

EXEMPLO CONCEITUAL — ISBN-13
^97[89][0-9]{10}$

Estado inicial → leitura → aceitação/rejeição
Aplicação

Entrada confiável

A validação lexical evita que dados com formato inválido avancem para as regras de negócio ou persistência, reduzindo entradas inconsistentes e tornando o comportamento mais previsível.

Entrada → Validação → Aceita / Rejeita → Processamento
Nível 2 · Análise sintática e memória estruturada

Autômatos de Pilha e dados estruturados

O projeto atual não possui um módulo próprio de parsing de XML ou JSON implementado. Porém, a análise torna-se relevante na evolução prevista para Google Books e Open Library, que retornam dados estruturados. Nesse cenário, o conceito de memória auxiliar dos Autômatos de Pilha ajuda a compreender aninhamento e correspondência estrutural.

CENÁRIO FUTURO
API → JSON estruturado → Parser → Objetos C# → MySQL

A teoria é apresentada como análise da futura camada de interpretação, não como funcionalidade já implementada.

06 · Complexidade computacional

Quanto custa
processar?

Analisar complexidade significa observar como o custo cresce conforme aumenta a quantidade de dados. No PI, isso se relaciona principalmente às operações de busca, cadastro e movimentação.

Operações de acervo

Uma busca que percorra todos os registros pode ter custo O(n), onde n representa a quantidade de registros analisados. A validação de uma entrada depende do tamanho m da entrada.

OperaçãoAnálise conceitual
ValidaçãoO(m)
Busca sem índiceO(n)
CadastroO(1) por operação*
Atualização localizadaO(1) em cenário ideal*
*Análise simplificada; custos internos do SGBD não estão detalhados na documentação do PI.

P vs NP no PI

O projeto não apresenta, na documentação atual, um problema central de otimização combinatória que exija uma solução NP-difícil. Portanto, não há justificativa para introduzir heurísticas apenas por causa da teoria.

DECISÃO DE ENGENHARIA

Problema atual → tratável
Escala institucional → limitada
Heurística → não necessária
Prioridade → simplicidade + previsibilidade

Saber quando não usar uma técnica também é maturidade.

A análise de complexidade permite justificar soluções simples. Para o escopo atual da biblioteca, não há necessidade de transformar uma operação administrativa em um algoritmo de otimização complexo.

viável e evolutiva.
